# COMEX 黄金库存数据链路说明

本文件记录库存数据的来源口径、核验分级、每日更新方式，以及**为什么这样设计**。
改代码前请先读完「日期口径」一节——这里踩过坑。

## 二、数据来源

| 来源代号 | 说明 | 频率 | 字段 | 历史深度 |
| --- | --- | --- | --- | --- |
| `eastmoney` | 东方财富 `RPT_FUTUOPT_GOLDSIL` 接口 | 日频 | 仅 `total` | 2021-10 起 |
| `metalcharts` | metalcharts.org 免费周频 CSV | 周频 | `registered` / `eligible` / `total` | 2026-02 起 |
| `cngold` | 旧方式：DeepSeek 搜索文章 + 正则解析 | 零散 | 三者都有但**已证伪** | 已作废 |

**为什么弃用 cngold**：旧方式依赖搜索零散文章再用正则解析，存在两个无法根治的问题——

1. **日期口径错误**：文章标题写「10月16日」，但表格里的日期标签比 CME 真实业务日早 1 天；
2. **字段跨日期拼接**：同一行内 `registered` / `eligible` / `total` 可能来自不同日期。
   三者加总自洽（所以旧的加总校验查不出来），但与权威源逐字段比对时对不上。

实际后果：数据库里曾把 `2026-10-15`、`2026-10-16` 两条错位重复数据标记为已核验，
其数值分别与 `10-13`、`10-14` 完全相同。

**CME 官方源当前不可用**：`www.cmegroup.com` 在本地网络持续连接超时，
因此退而采用上述两个结构化公开源，并用跨源比对相互校验。

## 三、日期口径（重要）

所有来源的 `report_date` 统一为 **CME 业务日**，原始日期保留在 `source_date` 列。

| 来源 | `source_date` 相对业务日 | 偏移量 |
| --- | --- | --- |
| `eastmoney` | 相同 | **0** |
| `metalcharts` | 相同 | **0** |

### 东方财富偏移为 0 的证明（排除法）

1236 条日频记录呈完美的周一至周五分布、零周末：

- 若 `source_date` = 业务日 −1，则应出现周日且不含周五 → 实际有 247 个周五、零周日，**排除**
- 若 `source_date` = 业务日 +1，则应出现周六且不含周一 → 实际有 231 个周一、零周六，**排除**

故偏移为 0。**早期实现曾误设为 +1，凭空制造出 247 个周六业务日。**

### 为什么偏移自检必须带业务日硬约束

`detect_date_offset()` 用「值变化日」交叉比对两源来确定偏移。但仅看匹配数会误判：

```
匹配数：    -2: 0    -1: 0    0: 6    +1: 21    +2: 10
周末数：   -2: 487  -1: 231  0: 0    +1: 247   +2: 496
```

`+1` 的匹配数（21）明显高于 `0`（6），纯按匹配数会再次选中错误的 `+1`。
原因是 COMEX 库存经常连续多日不变（实测 16.1% 的相邻记录数值完全相同），
一段持续不变的值在多种偏移下都能「碰巧」对上。

因此检测器有两条硬约束：

1. 只用**值变化日**参与匹配（持续不变的值没有判别力）；
2. **校正后产生周末日期的偏移直接判为无效**——CME 业务日只可能是周一至周五，
   这是定义级约束，优先级高于匹配数量。

此外 `run()` 中还有一道独立的**业务日校验闸门**：任何原因导致的日期错位，
只要产生周末日期就会中止入库，不会静默写进数据库。

## 四、四级核验状态

写在 `comex_inventory_quality` 表，由采集程序自动判定，也可在页面人工干预。

| 状态 | 含义 | 参与量化打分 |
| --- | --- | --- |
| `VERIFIED` | 与第二来源在 ±1 天窗口内总库存一致（偏差 ≤ 0.01%） | ✅ |
| `ACCEPTED` | 单源数据，通过全部自动校验且无告警 | ✅ |
| `REVIEW` | 存在告警：跨源分歧、极端变化、周末日期或校验未通过 | ❌ |
| `REJECTED` | 已证伪，保留数据供审计但不参与任何分析 | ❌ |

**为什么需要 `ACCEPTED`**：免费且带注册/合格拆分的源只有 metalcharts 周频 CSV，
与日频源的重叠区间只有 31 个业务日。若要求「必须有第二来源交叉验证」，
日频源的上千条记录将永远无法使用。因此对单源数据采用次级信任，
并把可信度差异如实记录在 `status` 与 `reason` 中。

### 跨源比对为什么用 ±1 天窗口

两源对「同一个观测挂在哪一天」的约定不同：周频源常用**发布日**（周五）标注，
其数值等于日频源**前一业务日**（周四）的库存。若只按完全相同的日期比对，
这 24 个重叠观测会被全部误判为冲突，反而淹没真正的异常。

因此冲突判定收紧为：窗口内能找到另一来源的数据，但没有任何一天的数值对得上，
才算冲突——说明确实存在无法解释的分歧。当前实测：**一致 74 组，冲突 0 组**。

### 因子层不再做同日冲突判定

`prepare_inventory()` 按 `INVENTORY_SOURCE_PRIORITY` 为每个业务日选出单一取值，
而不是同日精确比对判冲突。原因同上——那会把主源有效的日频数据一起丢掉（实测丢 22 天）。
数据质量的裁决已在采集层完成并写入核验状态，因子层只负责选数。

**所有字段只取自主源的同一行，绝不跨源拼字段**——旧 cngold 脏数据正是拼接而成的。

## 五、每日自动更新

### 手动执行

```powershell
# 三条数据链全部更新（行情 / 宏观 / 库存）
python -m scripts.daily_update --commit

# 只更新库存
python -m scripts.daily_update --commit --only comex

# 预览，不写库
python -m scripts.daily_update
```

### 注册 Windows 计划任务

```powershell
# 注册：每日 08:30 自动执行
powershell -File scripts\register_daily_task.ps1

# 指定时间
powershell -File scripts\register_daily_task.ps1 -Time "18:00"

# 查看状态
powershell -File scripts\register_daily_task.ps1 -Action show

# 注销
powershell -File scripts\register_daily_task.ps1 -Action unregister
```

任务特性：失败自动重试 3 次（间隔 10 分钟）、最长执行 1 小时后强制结束、
仅接通电源时运行、输出重定向到 `data\daily_update\` 下的日志。

> 注册计划任务会修改系统状态，需自行执行；本项目不会自动注册。

### 安全性

- **幂等**：三步都按唯一键去重，重复运行、手工补跑、重启后补跑都安全。
  实测连续运行两次，第二次结果为「新增 0，更新 0，无变化 1272」。
- **步骤隔离**：单步失败只记录并继续。例如行情源 xaus.com 返回 503 时，
  宏观与库存仍会正常更新完成。
- **留痕**：结果写入 `data\daily_update\last_run.json`，含各步耗时、
  失败原因与堆栈、表行数变化、核验状态分布。

## 六、库存因子口径

`f_inventory` 在 `src/quant/factors.py`：

| 配置项 | 值 | 说明 |
| --- | --- | --- |
| 指标口径 | `total` | 日频源只有总库存；注册/合格拆分仅周频可得 |
| 回看窗口 | 7 个日历天 | 用日历天而非报告条数，日频与周频都表示「一周变化」 |
| 公布滞后 | 1 天 | 业务日次一日才可用，避免未来函数 |
| 死区 | 0.5% | 小于该幅度的变化视为中性，避免噪声翻转信号 |
| 方向 | 库存下降为利多 | 实物交割需求走强 |

基期按日历天回溯取「`date − 7天` 当天或之前最近的观测」，
用 `merge_asof(direction="backward")` 实现，**不会取到未来值**。

## 八、已知限制

1. **注册/合格拆分只有周频**，且仅覆盖 2026-02 之后。
   因子因此采用总库存口径；若需注册库存口径，需取得 CME 官方日频数据。
2. **行情链依赖 xaus.com**，该接口本次测试返回 503。
   `.env` 中的 `GOLD_API_KEY` 为空。行情更新失败不影响库存与宏观。
3. **3 条 REVIEW 记录是真实的库存骤降事件**（2026-09-21、09-25，
   eligible 库存单日减少约 400 万盎司 / 127 吨），并非数据错误。
   系统保守地标记待复核而不自动判错，符合设计意图。
